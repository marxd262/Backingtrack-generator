# Backingtrack Generator

**Live version:** <https://marxd262.github.io/Backingtrack-generator/>

Generates backing tracks for practice in the browser (drums, bass, chords, pad, plus an optional lead and percussion) from a key, a style, a tempo and tags.
Plain JavaScript (ES modules), no build step, no runtime dependencies. The sound is synthesised with the Web Audio API, so everything runs offline.
The variant number on the start page is editable (1 to 9999): the same number in the same key always gives the same chord progression.

The interface is available in German and English (switch in the top right corner).

## Getting started

```sh
npm install
npm start
```

Then open <http://localhost:4173/ui/index.html> in your browser (the server only listens on localhost).

Developer page for listening to all styles (funk-rock, psychedelic indie, dreamy, blues shuffle, classic rock, hard rock, reggae, country, pop-punk): <http://localhost:4173/ui/render-harness.html>

## The interface

- **Start page:** the opening sentence (key and scale, style, tempo), the variant number, **Go** and **Fine-tune**. While playing, Go reads "Stop" and "To play page" leads back.
- **Play page:** a rack in the style of a modular synth, one screen that never scrolls (below 768 px wide everything stacks and the page scrolls vertically). The **header** holds Play/Stop, LCDs for the bar, the part and the current chord, the variant switch (‹ › and the dice), the app name (back to the start page, playback keeps running), the **Focus/Setup** switch, **Profiles** and the language. Below it the **visualisation**: the **Key** module (key, scale and, while playing, the next chord with a countdown), the **fretboard**, the **chord wheel** with the progression, and **Form & lanes** (the strip of song parts above the timeline, with a name label per lane, struck through when muted). **Focus** shows only the header and the visualisation, as large as the window allows; **Setup** adds the settings: the field **Whole song** (template, target size, four knobs) left of the strip, the settings of the chosen part right of it, and below the visualisation the **rack** with the modules Harmony, Rhythm, Character, one module per instrument and the Mixer. The rack scrolls inside itself, vertically and horizontally. The browser remembers the choice (`localStorage`, key `backingtrack.layout`). Knobs are native range inputs with a picture on top (drag up/down, arrow keys, Home/End), choices are LCD displays with arrow keys. The start page's **Fine-tune** opens the play page in Setup.
- **Mixer:** the last module of the rack (Setup) has one vertical fader per layer (drums, bass, chords, pad, lead, percussion) and one for the overall volume, 0 to 100 % (100 % is the normal level; it can only get quieter, never louder), plus a **Mute** key per layer (the only place to mute; the lane name beside the lanes is display only and is struck through while muted). The **All samples** key switches every instrument to a sample voice (and back to the classic synth); it reads Mixed when the instruments differ. Next to it sit the master sound knobs (brightness, echo, reverb). Everything acts live without a restart. The browser remembers the fader positions (`localStorage`, key `backingtrack.mix`), but not the mutes.
- **Switching the variant:** in the play page header, ‹ and › step the variant number (after 9999 comes 1, before 1 comes 9999) and the dice picks a random one. The pattern, the playing style (a little swing, syncopation and bass movement within what the tags allow) and the tone colour change with it, as do the knob values that are not set by hand; tags, tempo, length, mixer and mutes stay. The chord progression is derived anew from key and number (a custom progression is dropped, as on the start page). While playing, it continues in the current bar instead of bar 1, also when the variant is chosen on the start page.
- **Sound tags:** four groups of their own (drum sound, bass sound, chord sound, pad sound; the lead and the percussion have none) plus moods such as dark, bright and warm shape the sound. The notes stay the same; only "dreamy" also shifts the pad voicing, as before. The styles use them. Picking a tag or a style while playing takes effect live, without a restart.
- **Chords:** 17 chord types (triads incl. sus2, sus4, augmented and power chords; sevenths; sixths, add9 and ninths). The **Add chord** area works in two steps: pick a root of the key, then a chord type (only the types that fit that step are enabled). **Chord colour** rewrites the whole progression as triads, sevenths, extended chords or power chords and also applies to every newly generated progression (key, scale or variant change). Styles bring a chord colour of their own (blues: sevenths, hard rock and pop-punk: power chords; with variants, about one in four uses a fallback colour: extended chords, or plain triads); a colour you pick yourself is kept until you pick a style again. A new chord type is one entry in `src/core/chords.js` plus its names in the two language files, see `docs/interface.md`.
- **Rhythm:** the **Rhythm** module of the rack has the tempo knob and picks a time signature (4/4, 3/4, 6/8, 12/8 or 5/4), one of the grooves of that time signature (for example waltz, 6/8 ballad, 12/8 shuffle, five-four) and a **complexity** knob (more ghost notes, denser hi-hat, more syncopated kicks and bass movement). Groove and complexity act live; changing the time signature restarts playback, converts the tempo so the eighth-note speed stays the same (4/4 at 100 becomes 6/8 at 67) and gives every bar the beats of the new time signature. In the track format `bpm` counts the beats of the time signature (dotted quarters in 6/8 and 12/8). A new groove is one entry in `src/core/grooves.js` plus its name, see `docs/interface.md`.
- **Song form:** a song is a row of **parts** (intro, verse, build, chorus, break, outro) instead of a plain loop, so you hear structure. The app starts with a form rolled for the style (template "Auto", target 96 bars). In the **Whole song** field (left of the strip, Setup), **Template** picks Auto (follows the style, shown as "Auto (Pop)"), Jam, Pop, Build & Drop, Blues, Rock or **No form** (the song loops as before, and the field's **Target size** reads "Length"). **Target size** is 24, 32, 48, 64, 96, 128 or 192 bars; the rolled form lands within 4 bars of it (Blues: parts of 12 bars). Rolling follows guardrails: it starts with an intro or verse and ends with an outro or chorus, a build only leads into a chorus, a break is never first, last or doubled, no three equal parts in a row, at least one chorus from 24 bars (not in Jam). Each part type brings its own layers, density, level, transition and crash (intro: chords, pad and bass, quiet; verse: bass, drums, chords; build: rising; chorus: everything, the loudest and densest, with a crash on the one; break: only pad and chords; outro: fading). The level is in dB relative to the chorus and never above it; the chord progression starts again at its first chord in every part. **Transitions** into a part are none, a drum fill, a snare roll or a stop (one or two beats of silence). The four knobs: **Structure** (how many different parts are rolled; takes effect when you release it), **Dynamics** (how far the parts differ in level and density; 60 % is the default table, 0 makes all parts like the chorus, up to 130 %), **Pauses** (how often a layer drops out for one bar at the end of a phrase, and how long a stop is) and **Randomness** (how often a layer picks a new pattern every 4 bars). Dynamics, Pauses and Randomness act live; changing the total length restarts playback at the same position. Above the lanes a **strip** shows the parts (width = bars, height = level; arrow keys, Home and End select, click or Enter selects one); right of it, the settings of the chosen part (Setup): type, length, level, density, transition, crash, lock, move left or right, duplicate, delete. Editing a part **locks** it; a locked part stays where it is and keeps its settings when you press **Roll again** (in the Whole song field, next to **Add part**; same variant, different parts), switch the variant, change the style (with Auto) or release Structure. Changing the template or the target size rolls everything anew and releases the locks. **Add part** appends a locked verse of 8 bars. Limits: 64 parts, 64 bars per part, 512 bars in all. The form is the tenth part of a profile ("Song form"). Rules, numbers and the track format: `docs/interface.md`.
- **Layers:** six layers, each with its own mixer fader, mute key, timeline lane and voice choice: drums, bass, chords, pad, **lead** and **percussion**. The list lives in one place (`src/core/layers.js`); the audio, the mixer, the lanes and the track format derive from it. A new track has drums, bass, chords, pad and lead on and percussion off (its mute chip and mixer row are there, the layer just has to be switched on). The lead plays where the chords play, the percussion where the drums play.
- **Lead job:** the lead layer is on but silent until the **Lead job** display in its instrument module picks what it plays: Off (default), Fills (a short phrase at the end of a bar, in the second half of a section), Arpeggio (a run through the chord tones), Melody (long, sparse notes) or Call and response (a phrase in one bar, the answer in the next). One note at a time, always in the key. Changing the job works live.
- **Percussion part:** the **Percussion part** display in the percussion module picks the instrument: Mixed (default: shaker, tambourine and congas together), Shaker, Tambourine, Congas, Bongos, Claves or Cowbell. The patterns follow the groove and its time signature, the density follows the same parameters as the drums. Changing the part works live.
- **Voice choice in the UI:** each of the six instrument modules (drums, bass, chords, pad, lead, percussion) has a voice display with arrow keys (grouped into synthesis and samples, one entry per variant; the string models are hidden from the list for now), an SMP/SYN tag and a loading state for sample voices; knobs a voice does not use are dimmed. Choosing a voice works live and survives a style change.
- **Sample voices:** every layer can also play recorded samples taken from the MIT-licensed MuseScore_General soundfont (credits and licence text: `src/assets/samples/LICENSE-MuseScore_General.md`). Drums: standard, brushes, rimshot, jazz, electronic and 808 kits. Bass: finger, pick, upright. Chords: guitar, electric piano, organ, muted guitar, jazz guitar, funk guitar, steel-string, nylon and 12-string guitar, plus a clean and a jazz electric guitar from the CC0 FreePats FSBS sound banks (44.1 kHz, long natural decay; `src/assets/samples/LICENSE-Freepats-FSBS.md`). Pad: strings, warm. Lead: flute, sax, synth. Percussion: studio (shaker, tambourine, cowbell, bongos, congas, claves). The 25 sample packs (about 46 MB in total, from under 0.1 to 2.8 MB each, the two FreePats guitars 10.4 and 7.4 MB) load only when such a voice is chosen; until they are ready the classic synth keeps playing. The sample guitars play more naturally: a velocity curve and a velocity-dependent low-pass, no buzzing end loops on held notes, and a small seeded random variation per stroke, all adjustable as tunables in `render-harness.html`; `node scripts/render-ab.mjs` renders before/after WAVs for comparison.
- **Rebuilding the sample packs:** the soundfont is not in the repository (39.9 MB, [MuseScore_General.sf3](https://ftp.osuosl.org/pub/musescore/soundfont/MuseScore_General/MuseScore_General.sf3)). With it downloaded and `ffmpeg` installed, `node scripts/extract-samples.mjs <MuseScore_General.sf3> [output folder]` cuts the packs (`src/assets/samples/<layer>-<variant>.json` and `.pcm`) out of it; add `--fsbs-clean <file.sf2>` and `--fsbs-jazz <file.sf2>` (the small SF2 files from the FreePats release archives, URLs in the licence note) to rebuild the FreePats packs too, packs whose source is not given are skipped; which presets go into which pack is the `PACKS` table in the script. The rimshot kit is no pack of its own: it remaps keys of the standard kit.
- **Profiles:** the "Profiles" button in the header opens a window with a tree: "Current session", the read-only folder "Factory profiles" (the 9 styles) and "My profiles" with your own nested folders (up to 8 levels) and profiles, stored in the browser. A profile holds only the parts you tick when saving, out of 10: key, chords and meter; tempo; groove, complexity and length; style and tags; sound knobs; voices and jobs; layer switches; mixer levels; variant; song form (the sections, their locks and the four knobs; not available with "No form"). A profile without the song form leaves your form alone, except that a profile with a length but no song form re-rolls your form for that length only if it maps to a different target size (otherwise form and locks stay). Loading changes only what the profile contains and leaves the rest of the session alone (a tempo saved in 4/4 is converted when loaded into 6/8 or 12/8, like switching the meter); if the result would be invalid, nothing changes. "Overwrite with session" replaces only the parts you tick. Names are unique within a folder (case-insensitive). Loading a factory profile does what picking that style used to do (style, tags, tempo, chord colour, sound knobs reset); the old quick-pick chips are gone, the start page keeps its style cards. Rename, delete, create sub-folders, and move entries with "Move to ..." or by dragging the grip (mouse at once, touch and pen after a long press, so scrolling still works). Export and import follow the selection: the session, a profile or a whole folder as a `.json` file or as text, plus "Back up everything" for all of "My profiles" (importing a backup adds its entries to the chosen folder one by one, all 8 levels intact). Reading is tolerant: unknown fields are ignored, invalid ones are skipped and counted, only broken input is refused; old profile files (version 1) and the old flat list in the browser still import. Delete, move, overwrite and import offer one level of "Undo" (stored profiles only, never the session). Handy for sharing exactly what you hear when something sounds off. Format and rules: `docs/interface.md`.
- **Selectable voices (phase A):** every layer can use different sound generators: the classic synth (default, unchanged), plucked-string models (electric bass, clean electric guitar), an FM electric piano and the sample voices above. Voices are chosen per layer in the track (`voices`) and can be switched live; `render-harness.html` lets you audition them and tune their inner values, `spectrogram.html` shows what they sound like as a spectrogram.
- **Sound knobs:** every sound parameter of every instrument (37 in total, in groups for drums, bass, chords, pad, lead and master, for example fuzz, sub, drum room, reverb and echo) has a knob. Bass, chords, pad and lead each have three guitar-style effects in series on the whole layer (overdrive after a Tube Screamer, distortion after a RAT, fuzz after a Fuzz Face plus Big Muff stage, then a speaker cabinet); the drums and the percussion have none. The percussion shares the drums' room (reverb send) knob. Tags set the starting values; a moved knob overrides only its own parameter and wins over the tags. Each instrument module has a Reset button, and picking a style clears the overrides. Knobs act live without a restart.
- **Fretboard:** 22 frets, shows all notes of the scale, highlights the current chord and marks the next one (a legend explains the marks in Focus). The **Names/Degrees** switch changes the labels (degrees count from the root of the key); the **Real frets/Even width** switch chooses real fret spacing or equal widths. On a window too narrow for the board only the board scrolls sideways.

## Tests

```sh
npm test          # logic tests (node:test)
npm run test:ui   # everyday loop: UI and real-time browser tests only, no audio renders, fully parallel (about 1 min)
npm run test:e2e  # full pre-merge run: all browser tests incl. audio renders (Playwright, Chromium; once: npx playwright install chromium)
npx playwright test tests/e2e/play.spec.js --no-deps  # a single file
```

`test:ui` runs only the `realtime` project. The compute-heavy audio renders (project `offline`: `levels`, `sound`, `mix` and all `voices-*-sound` specs) run in `test:e2e` only, and first, so the real-time timers do not drift under load (without `--no-deps`, a single real-time file also runs `offline` first).
